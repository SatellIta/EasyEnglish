# Markdown 导入格式

## 1. 四个一级标题

```md
# words
# collocations
# sentences
# Scenery
```

- `# words`：单词，一行一个词条
- `# collocations`：短语 / 搭配
- `# sentences`：句子
- `# Scenery`：场景，规则见第 3 节

一行一个词条。明确是单词的目录（`# words` 或场景 `#### 单词`）可以用 ` / ` 分隔多个单词；短语、句子目录不要用 `/` 拆分。

## 2. 普通行与续行

### 行内释义

普通行可以使用 `=` 或 ` — ` 补充含义/解释：

```md
crack a joke = informal expression meaning tell a joke
If only ... — 要是...就好了
```

- 右侧含中文 → 写入「含义」
- 右侧不含中文 → 写入「补充解释」

### 给一个词条补充字段

紧跟在词条下面的缩进行（2 个空格或 Tab）可以继续补充字段。这是给一个单词写一句英文解释最直接的方式：

```md
deposit = 存款
  英英释义：To put money into a bank account.
  例句：I'd like to deposit $500.
  例句：She deposited the check.
  补充：也可以作名词，表示「存款」。
  音标：/dɪˈpɒzɪt/
  标签：finance, bank
```

可用的续行标签：

| 字段 | 可用标签 |
| --- | --- |
| 含义 | `含义` / `中文` / `meaning` |
| 英英释义 | `英英释义` / `英文释义` / `英文解释` / `definition` |
| 例句 | `例句` / `例子` / `example` |
| 补充解释 | `补充` / `解释` / `说明` / `explanation` |
| 笔记 | `笔记` / `备注` / `notes` |
| 音标 | `音标` / `发音` / `phonetic` |
| 标签 | `标签` / `tags` |

续行必须紧跟在词条下面；中间可以隔空行，但不能先写别的词条。

也可以用 `>` 引用行给上一条词条补例句：

```md
deposit = 存款
> I'd like to deposit $500.
> She deposited the check.
```

每个 `>` 行都是一个独立例句。`A = B` 里的 `B` 始终作为解释：含中文时写入「含义」，不含中文时写入「补充解释」。

多个例句用 ` / `、`；` 或 `<br>` 分隔；多个标签用逗号、分号或斜杠分隔。

## 3. Scenery 场景

推荐使用三级结构：场景 → 片段 → 类型。

```md
# Scenery

## At the bank

### Opening an account
#### 单词
deposit
withdraw

#### 短语
open an account
make a deposit

#### 句子
- I'd like to open a savings account, please.

### At the counter
#### 单词
withdraw cash
```

规则：

- `##` = 场景名称
- `###` = 场景下的片段 / 小节，可以自由命名（例如 `Opening an account`）
- `####` = 词条类型，支持：
  - 单词：`单词` / `words` / `word` / `词汇` / `vocabulary`
  - 短语：`短语` / `phrases` / `phrase` / `搭配` / `collocations`
  - 句子：`句子` / `sentences` / `sentence`
- 旧格式仍然兼容：`## 场景` 下面直接写 `### 单词` / `### 短语` / `### 句子`，不写片段也可以
- 片段下面的普通行按所在 `####` 的类型处理；没有 `####` 时按内容自动判断
- 在单词片段下，普通行可以用 ` / ` 分隔多个单词
- 场景中 `-` / `*` / `1.` 开头的列表行，一律按句子处理，即使写在 `#### 单词` 下，也不会按 `/` 拆分
- 场景词条默认加入每日复习；可以在导入预览里取消「场景词条也加入每日复习」
- 如果英文内容已经存在于词库，导入时不会新建词条，而是把已有词条关联到当前场景；已有词条的复习开关保持不变

导入后，`###` 片段会成为场景视图里的一级分组，`####` 类型会成为二级分组。

## 4. 表格

### 具名列（推荐）

表格使用具名列时，列的顺序可以任意调整，不需要的列可以省略：

```md
| English | 含义 | 英英释义 | 例句 | 音标 | 标签 |
| --- | --- | --- | --- | --- | --- |
| deposit | 存款；存入 | To put money into a bank account. | I'd like to deposit $500. / She deposited the check. | /dɪˈpɒzɪt/ | finance, bank |
| withdraw | 取款 | To take money out of an account. |  |  | finance |
```

支持的列名（中英文均可）：

| 字段 | 可用列名 |
| --- | --- |
| 英文内容 | `English` / `英文` / `单词` / `短语` / `句子` / `词条` / `内容` |
| 含义 | `含义` / `中文` / `释义` / `意思` / `Meaning` |
| 英英释义 | `英英释义` / `英文释义` / `英文解释` / `Definition` |
| 例句 | `例句` / `例子` / `Example` |
| 补充解释 | `补充` / `解释` / `说明` / `Explanation` |
| 笔记 | `笔记` / `备注` / `Notes` |
| 音标 | `音标` / `发音` / `Phonetic` |
| 标签 | `标签` / `Tags` |

- 第一列不一定是英文内容，只要表头能识别即可
- 没有英文内容列时，第一列会作为英文内容
- 多个例句用 `<br>`、` / ` 或 `；` 分隔；多个标签用逗号、分号或斜杠分隔
- 表格行的类型跟随所在 `#` / `####` 分类
- 第一列为空的表格行会被丢弃

### 旧三列

旧的 `| English | 含义 | 补充 |` 三列表格仍然可用。如果表头完全无法识别，也会按「第一列英文、第二列含义、第三列补充解释」解析，并在预览中提示。

## 5. 忽略不想导入的内容

用 HTML 注释包住备注、草稿或临时说明，解析时会整体跳过：

```md
<!-- 这一段是给自己看的备注，不导入 -->
deposit = 存款

<!--
整段多行注释
不会成为词条
-->
```

也可以写在行内：`deposit <!-- 来源：播客 --> = 存款`。`<!--` 和 `-->` 成对即可，不要求独占一行。未闭合的注释会给出提示，并忽略其后的内容。

## 6. 其他规则

- 表格以外的每个非空行就是一条候选词条，不会把多行合并成一条（缩进续行除外）
- `H5` 及更深的标题会被忽略；普通分类里的 `H4` 也不参与分组
- 加粗、斜体、反引号、Markdown 链接会去掉格式，只保留文字
- 场景中没有类型标题时，会按内容自动判断词条类型
- 导入前会按主要英文内容查重：
  - 忽略大小写、首尾空格、首尾引号和结尾标点
  - 类型、含义、解释、例句、标签不参与判重
  - 已存在的英文内容不会新建；如果它在场景里，会直接把已有词条关联到该场景，并保留原有复习开关
  - 勾选「更新已存在词条的内容」时，只更新 Markdown 里实际写了的字段；没写的例句、音标、笔记等保持原样
  - 需要同步 Markdown 文件时，可以在设置里配置路径，再从复习页一键同步

## 7. 导出

导出的 Markdown 使用同一套结构，可以再次导入：

- 常规词条：`# words` / `# collocations` / `# sentences`
- 场景：`# Scenery` → `## 场景名` → `### 片段` → `#### 单词/短语/句子`
- 表格使用具名列：`English | 含义 | 英英释义 | 例句 | 补充 | 笔记 | 音标 | 标签`
- 只会输出该分组里实际有内容的列
- 导出不包含复习进度和图片
