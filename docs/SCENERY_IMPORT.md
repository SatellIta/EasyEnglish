# Markdown 导入与 Scenery 场景设计

这份文档说明 EasyEnglish 识别手写英语笔记的规则，以及 `# Scenery` 如何保存、展示和导出。

## 目标

- 用一套明确、可预测的 Markdown 规则把笔记导入词库。
- 普通分类（单词、搭配、句子）进入每日复习。
- `# Scenery` 是联想记忆空间：H2 是场景，H3 是场景片段，H4 是单词/短语/句子分类。
- 一个词条可以拥有中文含义、英英释义、例句、补充解释、笔记、音标和标签。
- 导入和导出使用同一套结构，方便备份和再次导入。

## 数据模型

```text
entries                      词条本体
  review_enabled             是否进入每日复习，默认 1
  meaning                    中文含义
  english_definition         英英释义（可以是一整句解释）
  explanation                补充解释
  examples                   例句 JSON 数组
  notes / phonetic / tags    笔记、音标、标签
scenes                       场景
  id, name, description
scene_entries                场景与词条的多对多关系
  scene_id, entry_id
  section                    场景内 H3 片段名（旧数据为类型标签）
  subsection                 场景内 H4 标题（新导入通常是类型标签）
  position                   导入或添加顺序
  added_at                   加入时间
```

一个词条可以属于多个场景。场景成员关系本身不改变复习调度；复习队列只看 `entries.review_enabled`。

场景词条默认 `review_enabled = 1`，和普通词条一样进入每日复习；可以在导入预览里取消「场景词条也加入每日复习」，或在场景详情页批量移出复习。

## Markdown 规则

### 普通分类

```md
# words
# collocations
# sentences
```

- `# words`：一行一个词条，类型固定为单词
- `# collocations`：一行一个词条，类型固定为短语
- `# sentences`：一行一个词条，类型固定为句子
- 明确是单词的目录（`# words` 或场景 `#### 单词`）可以用 ` / ` 分隔多个单词；短语、句子目录不拆分

普通行可选使用 `=` 或 ` — ` 补充释义：

```md
crack a joke = informal expression meaning tell a joke
If only ... — 要是...就好了
```

- 右侧含中文 → `meaning`
- 右侧不含中文 → `explanation`

非场景分类的 H2/H3 会进入预览分组，并作为标签保存。

### 续行

紧跟在词条下面的缩进行（2 个空格或 Tab）可以补充独立字段：

```md
deposit = 存款
  英英释义：To put money into a bank account.
  例句：I'd like to deposit $500.
  例句：She deposited the check.
  补充：也可以作名词。
  音标：/dɪˈpɒzɪt/
  标签：finance, bank
```

支持的标签：`含义` / `中文`、`英英释义` / `英文释义` / `definition`、`例句`、`补充` / `解释`、`笔记`、`音标`、`标签`。

`>` 引用行可以作为上一条词条的例句，每个 `>` 行都是一条独立例句。`A = B` 里的 `B` 始终作为解释：含中文时写入 `meaning`，不含中文时写入 `explanation`。

### Scenery

推荐的新结构：

```md
# Scenery

## Bank

### Opening an account
#### 单词

Deposit money
ATM vestibule
- I'd like to deposit $500 into my savings account.

#### 短语

make a withdrawal
withdraw cash

#### 句子

Can I deposit cash at this ATM?

### At the counter
#### 单词

withdraw cash
```

映射关系：

- `##` → 场景名
- `###` → 场景片段（自由命名），保存到 `scene_entries.section`
- `####` → 类型：单词 / 短语 / 句子，保存到 `scene_entries.subsection`
- 普通行 → 按所在 `####` 的类型；没有 `####` 时按内容自动判断
- 单词片段下的普通行可以用 ` / ` 分隔多个单词
- 列表行（`-` / `*` / `1.`）→ 在场景中一律按句子，即使写在 `#### 单词` 下，也不按 `/` 拆分

旧格式继续兼容：在 `## 场景` 下直接写 `### 单词` / `### 短语` / `### 句子`，不写片段层。此时 `section` 保存为类型标题，`subsection` 为 `null`。

支持的类型标题（H3 或 H4）：

| 类型 | 可用标题 |
| --- | --- |
| 单词 | `单词` / `words` / `word` / `词汇` / `vocabulary` |
| 短语 | `短语` / `phrases` / `phrase` / `搭配` / `collocations` |
| 句子 | `句子` / `sentences` / `sentence` |

### 表格

表格支持具名列，顺序任意、可省略：

```md
| English | 含义 | 英英释义 | 例句 | 音标 | 标签 |
| --- | --- | --- | --- | --- | --- |
| Deposit money | 存钱 | To put money into an account. | I'd like to deposit $500. / She deposited the check. | /dɪˈpɒzɪt/ | finance, bank |
| Bank account | 银行账户 | An account held with a bank. |  |  | finance |
```

支持的列名（中英文均可）：

| 字段 | 可用列名 |
| --- | --- |
| 英文内容 | `English` / `英文` / `单词` / `短语` / `句子` / `词条` / `内容` |
| 含义 | `含义` / `中文` / `释义` / `意思` / `Meaning` |
| 英英释义 | `英英释义` / `英文释义` / `英文解释` / `Definition` |
| 例句 | `例句` / `例子` / `Example` |
| 补充解释 | `补充` / `解释` / `说明` / `Explanation` |
| 笔记 | `笔记` / `备注` / `Notes` |
| 音标 | `音标` / `发音` / `Phonetic` |
| 标签 | `标签` / `Tags` |

- 英文内容列不必在第一列；没有识别到英文列时，第一列作为英文内容
- 多个例句用 `<br>`、` / ` 或 `；` 分隔；多个标签用逗号、分号或斜杠分隔
- 单元格里的竖线用 `\|` 转义
- 第一列为空的表格行会被丢弃
- 表格行的类型跟随所在 H1 / H3 / H4 分类

旧的 `| English | 含义 | 补充 |` 三列表格仍然可用。表头完全无法识别时，解析器按前三个位置解析，并在预览中提示。

## 注释与忽略内容

HTML 注释不参与解析，支持单行、行内和跨行：

```md
<!-- 给自己看的备注，不导入 -->
deposit = 存款

<!--
整段草稿
不会成为词条
-->
```

行内注释也可以：`deposit <!-- 来源：播客 --> = 存款`。`<!--` 与 `-->` 必须成对；未闭合时会给出预览提示，并忽略其后的内容。

## 查重与复用

导入预览、提交、手动添加和编辑都按**主要英文内容**查重：

- 忽略大小写、首尾空格、首尾引号和结尾标点
- 类型、含义、解释、例句、标签都不参与判重

预览会标记数据库中或本批次内已存在的英文内容：

- 普通分组的重复项默认不勾选；场景分组的重复项默认勾选，因为提交时会复用已有词条并建立场景关联。
- 已存在且没有场景：默认跳过；勾选「更新已存在词条的内容」时只更新 Markdown 里实际提供了的字段（含义、英英释义、例句、补充、笔记、音标），没写的字段保持原样，标签取并集。
- 已存在且属于场景：写入 `scene_entries`，不会新建词条；如果这个词已经在同一个场景里，只更新 `section` / `subsection` 位置。
- 已有词条的 `review_enabled`、`learned_at`、错误率和来源都不变；「保留原有复习开关」是同步的硬性规则。
- 同一文本在文档里出现多次时，使用字段最完整的那一条作为内容来源，避免场景里的简写行覆盖完整释义；只有一个裸词时只建立场景关联，不会清空已有释义。

提交结果会分别返回 `created`（新建）、`linked`（复用已有词条或本批次先创建的词条）、`updated`（更新内容）和 `skipped`。

## 场景展示

场景详情按 `section`（H3 片段）分组，再按 `subsection`（H4 类型或自由标题）分组，并支持类型筛选：

- 默认按记忆时间排列；同一次导入的词条用导入位置保持顺序
- 可切换为导入顺序
- 卡片可编辑、删除或从当前场景移除

旧数据的 `section` 是「单词 / 短语 / 句子」，会直接显示为一级分组，保持原有体验。

## 导出

词库页提供「导出 Markdown」。用户可以选择：

- 常规单词 / 短语 / 句子（只包含未归入场景的词条）
- 一个或多个场景

导出结构：

```md
# words
| English | 含义 | 英英释义 | 例句 | 补充 | 音标 | 标签 |
| --- | --- | --- | --- | --- | --- | --- |
...

# Scenery
## Bank
### Opening an account
#### 单词
| English | 含义 | 英英释义 | 例句 |
...
#### 短语
...
#### 句子
...
```

- 表格使用具名列，只输出该分组里实际有内容的列
- 英英释义、例句、补充解释、笔记、音标和标签都是独立列
- 场景按 `section` 输出 `### 片段`，再按词条类型输出 `#### 单词/短语/句子`
- 如果场景没有片段（旧数据），直接输出 `### 单词/短语/句子`
- 不导出复习进度和图片
- 导出文件可以再次导入，字段会拆回独立列，不会合并成一段说明

## Markdown 文件同步

设置页的「Markdown 同步」可以保存一个本地文件路径；复习页会显示「同步 Markdown」按钮。

- 只接受 `.md` / `.markdown` / `.txt`，最大 2 MB；路径由运行 Hono 服务的电脑读取，支持 `~/`。
- 同步等于解析整份文件并勾选「更新已存在词条内容」：新建词条默认进入复习，已有词条更新内容但保留复习开关、学习状态、错误率和来源。
- 同步是增量的：Markdown 中删除的词条不会从词库删除，避免误删手动添加的内容。
- 复习页同步后会刷新到期统计；如果正在进行一轮复习，需要重新开始复习才能载入新词。

## 已知取舍

- 一行一个词条；缩进续行、`>` 例句续行和 HTML 注释只影响上一条词条或整段忽略，不支持任意多行合并。
- 仅在明确是单词的目录（`# words` / `#### 单词` / 旧版 `### 单词`）用 `/` 拆分；短语、句子目录不拆分。
- 场景导出的 H4 统一由词条类型决定；自定义 H4 标题不会在导出时保留。
- 已存在的英文内容再次导入到新场景时会复用并关联，不会新建重复词条。
- 不解析 Markdown 里的日期；导入时间就是记录时间。
- 场景描述不会自动从正文提取。
- 图片不会通过 Markdown 导入或导出。
- 文件同步是增量的，不会删除 Markdown 中已移除的词条。

## 后续可调整

- 导入时选择「跳过 / 更新已有 / 复用并建立场景关联」
- 导出为 JSON（保留完整结构化字段和复习状态）
- 场景拖拽排序、手动改小节名
- 导入后让 AI 补全释义、音标或例句
