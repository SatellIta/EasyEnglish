# Markdown 导入与 Scenery 场景设计

这份文档说明 EasyEnglish 如何识别手写英语笔记，以及 `# Scenery` 分类如何保存和展示。它同时是后续调整导入规则的依据。

## 目标

- 让已有的 Markdown 笔记可以一次性进入词库，而不是逐条复制。
- 普通分类（单词、搭配、句子）继续进入每日复习。
- `# Scenery` 是**联想记忆空间**，用于把同一场景下的词句放在一起看；场景本身不额外制造复习压力。
- 尽量保留原笔记的层级，尤其是 Scenery 下比较复杂的 H2/H3/加粗小标题。

## 数据模型

```text
entries                      词条本体（单词 / 短语 / 句子）
  review_enabled             是否进入每日复习，默认 1
scenes                       场景
  id, name, description
scene_entries                场景与词条的多对多关系
  scene_id, entry_id
  section                    H3 小节
  subsection                 加粗小标题 / 引导语
  position                   导入或添加顺序
  added_at                   加入时间
```

一个词条可以同时属于多个场景，也可以既在场景里、又进入每日复习。场景成员关系本身不改变复习调度；复习队列只看 `entries.review_enabled`。

### 为什么场景词条默认不复习

`# Scenery` 的内容通常是大批量的场景词汇和例句。如果导入后全部立即到期，会瞬间淹没每日复习队列。因此：

- 从 `# Scenery` 导入的词条默认 `review_enabled = 0`。
- 它们仍然存在于词库、日期视图、类型视图和场景视图中。
- 用户可以在词条编辑表单里勾选「加入每日复习」，或在导入预览中勾选「场景词条也加入每日复习」。
- 复习状态会照常创建；之后打开开关时从当前状态继续，不会丢失历史。

## Markdown 映射

| 笔记结构 | 导入结果 |
| --- | --- |
| `# words` | 每个普通行一个单词；`a / b / c` 拆成多个 |
| `# collocations` | 每个普通行一个短语；支持 `=`、`—` 拆分释义 |
| `# sentences` | 每个普通行一个句子；`##` / `###` 进入标签 |
| `# Scenery` + `## Bank` | 场景 `Bank` |
| `### Deposition money` | 场景小节 `Deposition money` |
| `**Natural conversations**` | 场景内加粗小标题，进入 `subsection` |
| `At a bank:` | 引导语，进入 `subsection` |
| Markdown 表格 | 每行一个词条；第一列英文，第二列释义，第三列解释 |
| `- "I'd like..."` | 去掉列表符号和引号后作为句子 |
| `text = explanation` | `text` 是正文；右侧含中文时进入 `meaning`，否则进入 `explanation` |
| `text — 中文` | 右侧进入 `meaning` |
| `text (note)` | 括号内容进入 `explanation` |
| 无法判断类型 | 预判为单词/短语/句子，可在预览里逐条改 |

### Scenery 的展示

场景详情页按以下层级展示：

```text
Scene（例如 Bank）
  └─ Section（例如 Deposition money）
       └─ Subsection（例如 Natural conversations · At a bank）
            └─ 词条卡片（单词 / 短语 / 句子）
```

- 场景详情默认按「记忆时间」排序；同一次导入的词条时间相同，因此用导入位置保持原笔记顺序。
- 可以切换到「导入顺序」，完全按原 Markdown 的出现顺序排列。
- 可以按单词 / 短语 / 句子筛选。
- 场景详情里的每张卡片可以编辑、删除，或从当前场景移除（不会删除词条本身）。

### 为什么用 H2 作为场景、H3 作为小节

你的笔记里 `# Scenery` 下是 `## Bank`、`## Food` 这样的生活场景，`###` 则是场景内的表达分组（存款、取款、账户等）。把 H2 作为场景、H3 作为小节，既能保持「场景」这一层的稳定，又不会让每个 H3 都变成一个独立场景。

加粗小标题和 `At a bank:` 这类引导语不适合单独建表，因此放在 `scene_entries.subsection` 里，作为展示时的二级分组。

## 词库整理

词库页有三种整理方式：

1. **按日期**：先展示有学习记录的日期，点进去看当天新增，再按单词/短语/句子筛选。
2. **按类型**：直接分单词、短语、句子三个区块，默认按记录时间从新到旧；区块默认折叠，点击展开，避免几百条一次性铺开。
3. **按场景**：先展示场景卡片，点进去按场景小节和词性子筛选，默认按记忆时间排列。

搜索框在三种视图里都可用；长列表按「显示更多」分批渲染，避免一次渲染几百条。

## 导入流程

1. 在词库页点击「导入 Markdown」，进入 `/import`。
2. 选择 `.md` 文件或直接粘贴文本（单次最大 2 MB）。
3. 点击「解析预览」。预览会显示总数、类型分布、场景数和疑似重复数。
4. 按分组展开检查；可以逐条改类型，也可以按组全选/取消。
5. 默认只选非重复项；需要重新导入已有内容时手动选中。
6. 勾选「场景词条也加入每日复习」可以改变场景词条的默认行为。
7. 点击「导入选中词条」。服务端会按「类型 + 文本」对本批次去重，并复用同名场景。

## 已知取舍

- 斜杠列表会拆成多个词条。`a crooked smile / tooth / picture frame` 会得到三个条目，而不是自动补全成 `a crooked tooth`。导入预览里可以改类型或删除不需要的条目。
- 场景内表格的第三列会进入 `explanation`，第二列进入 `meaning`；英文释义也放在 `meaning` 里，界面仍显示为「含义」。
- 没有自动调用 AI 清洗或补全释义。导入保持确定性，AI 整理可以在后续版本作为单独功能加入。
- 导入器只解析文本，不执行 Markdown 中的 HTML 或脚本。
- 场景名称不区分大小写唯一；重复导入会复用已有场景，不会创建 `Bank` 和 `bank` 两个场景。

## 后续可以讨论的调整

- 是否把 H3 也提升为独立场景，或提供「按 H2 / 按 H3 建场景」的导入选项。
- 是否为场景增加封面、颜色或排序方式。
- 是否在场景详情里支持拖拽排序和手动编辑小节名。
- 是否让 AI 在导入后补全缺失的中文释义、音标或例句。
- 是否提供「把场景词条一键加入复习」的批量操作。
