# Markdown 导入与 Scenery 场景设计

这份文档说明 EasyEnglish 识别手写英语笔记的规则，以及 `# Scenery` 如何保存、展示和导出。

## 目标

- 用一套明确、可预测的 Markdown 规则把笔记导入词库。
- 普通分类（单词、搭配、句子）进入每日复习。
- `# Scenery` 是联想记忆空间：H2 是场景，H3 是单词/短语/句子分类。
- 导入和导出使用同一套结构，方便备份和再次导入。

## 数据模型

```text
entries                      词条本体
  review_enabled             是否进入每日复习，默认 1
scenes                       场景
  id, name, description
scene_entries                场景与词条的多对多关系
  scene_id, entry_id
  section                    场景内分类标签（单词/短语/句子）
  subsection                 旧版数据可能保留；新导入为 null
  position                   导入或添加顺序
  added_at                   加入时间
```

一个词条可以属于多个场景。场景成员关系本身不改变复习调度；复习队列只看 `entries.review_enabled`。

场景词条默认 `review_enabled = 0`，因此不会额外增加每日复习负担。用户可以在词条编辑表单里重新打开复习，或在导入预览中统一打开。

## Markdown 规则

### 普通分类

```md
# words
# collocations
# sentences
```

- `# words`：一行一个词条，类型固定为单词
- `# collocations`：一行一个词条，类型固定为短语
- `# sentences`：一行一个词条，类型固定为句子
- 明确是单词的目录（`# words` 或场景 `### 单词`）可以用 ` / ` 分隔多个单词；短语、句子目录不拆分

普通行可选使用 `=` 或 ` — ` 补充释义：

```md
crack a joke = informal expression meaning tell a joke
If only ... — 要是...就好了
```

- 右侧含中文 → `meaning`
- 右侧不含中文 → `explanation`

非场景分类的 H2/H3 会进入预览分组，并作为标签保存。

### Scenery

```md
# Scenery

## Bank

### 单词

Deposit money
ATM vestibule
- I'd like to deposit $500 into my savings account.

### 短语

make a withdrawal
withdraw cash

### 句子

Can I deposit cash at this ATM?
```

映射关系：

- `##` → 场景名
- `###` → 分类：单词 / 短语 / 句子
- 普通行 → 按所在 H3 的分类
- `### 单词` 下的普通行可以用 ` / ` 分隔多个单词
- 列表行（`-` / `*` / `1.`）→ 在场景中一律按句子，即使写在 `### 单词` 下，也不按 `/` 拆分
- 场景内 `section` 保存为最终类型标签（单词/短语/句子），用于场景视图分组
- 新导入不再使用加粗小标题或 `At a bank:` 这类引导语做 subsection

支持的 H3 名称：

| 类型 | 可用标题 |
| --- | --- |
| 单词 | `单词` / `words` / `word` / `词汇` / `vocabulary` |
| 短语 | `短语` / `phrases` / `phrase` / `搭配` / `collocations` |
| 句子 | `句子` / `sentences` / `sentence` |

如果 H3 不是可识别的分类，解析器会按内容自动判断，并在预览中提示。

### 表格

表格可用于任何分类：

```md
| English | 含义 | 补充 |
| --- | --- | --- |
| Deposit money | 存钱 | 办理存款 |
| Bank account | 银行账户 | 可搭配 savings / checking |
```

- 第一列：英文内容
- 第二列：含义
- 第三列：补充解释
- 第四列及以后忽略
- 单元格里的竖线用 `\|` 转义
- 第一列为空的表格行会被丢弃
- 表格行的类型跟随所在 H1/H3 分类

## 查重

导入预览、提交、手动添加和编辑都按**主要英文内容**查重：

- 忽略大小写、首尾空格、首尾引号和结尾标点
- 类型、含义、解释、例句、标签都不参与判重

预览会标记数据库中或本批次内已存在的英文内容，默认不勾选。提交时会再次跳过已存在内容并返回 `skipped`。

当前取舍：如果某个英文内容已经存在，再次导入到新场景时会跳过，不会自动把已有词条链接到新场景。需要的话可以后续增加「复用已有词条并建立场景关联」的选项。

## 场景展示

场景详情按 `section`（单词/短语/句子）分组，并支持类型筛选：

- 默认按记忆时间排列；同一次导入的词条用导入位置保持顺序
- 可切换为导入顺序
- 卡片可编辑、删除或从当前场景移除

## 导出

词库页提供「导出 Markdown」。用户可以选择：

- 常规单词 / 短语 / 句子（只包含未归入场景的词条）
- 一个或多个场景

导出结构：

```md
# words
| English | 含义 | 补充 |
| --- | --- | --- |
...

# collocations
...

# sentences
...

# Scenery
## Bank
### 单词
| English | 含义 | 补充 |
...
### 短语
...
### 句子
...
```

- 使用三列表格：第一列英文、第二列含义、第三列补充
- 「补充」列合并解释、例句、笔记和标签
- 不导出复习进度
- 导出文件可以再次导入；再次导入时，例句/笔记/标签会作为补充文本保留在 `explanation` 中，而不是拆回独立字段

## 已知取舍

- 一行一个词条，不支持多行合并。
- 仅在明确是单词的目录（`# words` / `### 单词`）用 `/` 拆分；短语、句子目录不拆分。
- 表格只取前三列，第 4 列及以后丢弃。
- 场景 H3 不是可识别分类时会按内容自动判断，并在预览提示。
- 已存在的英文内容再次导入到新场景时不会自动建立新场景关联。
- 导出没有单独的例句/笔记/标签列，重新导入时这些内容会合并在「补充」里。
- 不解析 Markdown 里的日期；导入时间就是记录时间。
- 场景描述不会自动从正文提取。

## 后续可调整

- 导入时选择「跳过 / 更新已有 / 复用并建立场景关联」
- 更精细的表格列映射
- 导出为 JSON（保留完整结构化字段和复习状态）
- 场景拖拽排序、手动改小节名
- 导入后让 AI 补全释义、音标或例句
